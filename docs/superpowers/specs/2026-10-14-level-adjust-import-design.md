# 原始水准数据导入与平差设计

## 目标

在网页端数据录入页增加“原始数据导入”，支持 LEVELADJUST 使用的 `.DAT`、`.BM1`、`.hdf`、`.in1`、`.gco`、`.ou1`、`.our` 文本文件。用户选择按距离或按测站定权后，系统计算水准网平差高程，并让用户把平差点号映射到当前工程已有水准测项的数据库点号，确认后写入选择日期的“测量值”。

当前网页使用 FastAPI、SQLModel、React、TypeScript 和 SQLite/可配置 PostgreSQL。现有水准数据行的保存格式为 `时间`、`点号`、`测量值`、`备注`，项目写入带 `revision` 乐观锁，数据录入权限为 `data_entry`。

## 文件识别与解析

导入以同名文件组为单位。用户可以选择多个文件；也可以选择其中一个文件，系统在同一上传批次内按文件主名自动关联其他后缀。主文件名不一致时显示组内文件清单并要求用户确认，不按目录中的相似名称猜测。

解析器按 GB18030、UTF-8 顺序解码，并保留原始字节 SHA-256、文件名和编码。解析结果包含来源文件、行号和原始文本片段，错误显示到具体文件和行。

- `.DAT`：解析仪器记录中的测站、后视/前视、读数、距离、测点高程记录和闭合回点，保留原始观测记录。
- `.BM1`：解析 `点号,高程` 已知点表；点号去除外围空白，高程必须为有限数值。
- `.hdf`：解析逐测站的前后视读数、距离、测站高差、累计距离和累计高差。
- `.in1`：解析 `起点,终点,观测高差,权重因子,路线标志`。权重因子按文件中的单位保留，计算时按选定定权规则解释。
- `.gco`：解析闭合差、路线长度、限差和闭合环编号，用作计算后校验，不作为唯一计算输入。
- `.ou1`：解析平差后测段高差、改正数、残差和权重，用作交叉核验。
- `.our`：解析最终点号、高程、累计变化和日期，用作最终结果核验。

上传 `.DAT` 即可进入下一步：系统从仪器记录中提取点号和 `Z` 高程，明确提示“不做平差处理”，随后直接进入点号映射。上传 `.DAT` 与 `.BM1` 后执行平差；`.hdf`、`.in1`、`.gco`、`.ou1`、`.our` 均为可选派生/核验文件。缺少这些文件时由系统依据观测记录生成 GB18030 文本派生文件；提供的派生文件与重新计算结果不一致时，阻止写入并显示差异。

## 平差算法

新增纯 Python 模块 `backend/app/level_adjustment.py`，不执行 LEVELADJUST EXE，不依赖桌面程序。模块只接受解析后的结构化观测和已知点。

观测方程为：

```text
H_to - H_from = delta_h
```

已知点高程作为固定约束，未知点高程为待求量。按路线边建立设计矩阵，使用加权最小二乘求解；单闭合路线和多已知点网络均走同一个矩阵模型。输出每个未知点的平差高程、每条观测的改正数和残差、总路线距离、闭合差、单位权中误差、自由度、限差检查和求解警告。

定权规则：

- 按距离：每条边使用测段长度作为误差方差依据，长度必须为正；长度来自 `.hdf`，缺失时回退到 `.in1` 权重字段。
- 按测站：每条边使用测站数作为误差方差依据；无法从 `.DAT` 计数时使用 `.in1` 的权重字段并标记来源。

实现必须拒绝重复边、断开的点号、缺失观测高差、非有限数值、零/负权重、无已知点和秩不足矩阵。闭合差超出文件限差时，计算结果仍可预览，但写入按钮保持禁用，除非用户明确勾选“允许超限结果写入”并再次确认。

## 后端接口

在 `backend/app/api/routes/workspace.py` 增加两个受 `EntryProject` 保护的接口：

```text
POST /projects/{project_id}/level-adjustment/preview
  multipart/form-data: files[]、weight_mode、observed_date
  返回导入组摘要、解析诊断、平差结果、交叉核验、mapping_candidates、project_revision

PUT /projects/{project_id}/level-adjustment/apply
  JSON: revision、measurement_key、observed_date、mappings[]、weight_mode、allow_out_of_tolerance
  原子写入水准测项当前日期行，保存导入元数据和原始文件摘要，返回新的项目 revision
```

`mappings[]` 的每项为 `{adjusted_point, database_point, enabled}`。服务端重新校验点号属于当前平差结果、数据库点号属于目标测项，并使用请求中的 revision 防止覆盖并发修改。应用接口只更新所选日期对应的行，保留其他日期和备注；同一日期同一点号重复时返回定位明确的 422 错误。

新增结构化 Pydantic 模型放在 `backend/app/project_models.py`，解析模型和求解模型放在 `backend/app/level_adjustment.py`，原始文件落盘到 `data/projects/<project_id>/level-adjustments/<import_id>/`，项目 payload 只保存清单、摘要、计算参数、核验状态和结果引用，不保存未限制大小的原始文本。

## 前端交互

在 `frontend/src/pages/DataEntry.tsx` 的数据录入面板标题区域左侧增加“原始数据导入”按钮。按钮只对 `data_entry` 权限可见。

向导包含三步：

1. 文件选择：`.DAT` 必选，`.BM1` 可选，其余后缀可选；上传 DAT 后即可继续，编码/缺失/解析错误显示在向导中。
2. 平差设置：显示已知点、路线起终点、测段数、总长度、闭合差和限差；选择“按距离定权”或“按测站定权”；显示计算摘要和交叉核验差异。
3. 点号映射：左侧平差点号和高程，右侧目标水准测项及数据库点号选择；精确匹配自动勾选，模糊匹配只作为候选并要求确认；冲突、未匹配和禁用写入项必须可见。

平差预览成功后用户可下载系统生成的 `.hdf`、`.in1`、`.gco`、`.ou1`、`.our` 文件；DAT-only 预览不生成派生文件，完成映射后即可写入。平差结果只有质量检查通过或明确允许超限后才启用“写入今日测值”。写入成功后刷新项目、目录、当前期次和数据库查询缓存，并显示写入数量、跳过数量和未匹配点号。

## 测试与验收

后端测试新增到 `backend/tests` 或现有测试目录，先写失败测试再实现：

- 7 个样例文件均能用 GB18030 解析，`.DAT` 识别闭合回点 `Z2`，`.BM1` 得到 `Z2=-16.8744`。
- 样例 `.hdf`、`.in1`、`.gco`、`.ou1`、`.our` 的测段数、总距离、闭合差和点号集合相互一致。
- 按距离和按测站两种定权都能得到有限结果，样例关键点与 `.our` 在允许的小数误差内一致；权重模式变化会产生可解释的结果差异。
- 缺失文件、坏编码、重复点号、断网、无已知点、闭合超限、点号映射冲突和 revision 冲突都返回明确错误且不写库。
- 应用接口只更新目标日期和映射点，不删除其他日期、备注或未选点。

前端测试覆盖：按钮权限、向导步骤切换、自动匹配/冲突提示、质量检查失败时禁用写入、成功写入后的缓存刷新。完成后运行完整后端 pytest、前端测试和 `npm run build`。

## 限制与后续

本轮只覆盖文本格式水准导入和平差写回，不迁移桌面端 Word/Excel 报表、仪器驱动、串口读取或桌面工程模板美化。运行时不会执行上传的文件或外部 EXE。若后续发现其他工程使用不同的 `.DAT` 行式或多环网络，需要新增格式样例和对应解析测试后再扩展。
